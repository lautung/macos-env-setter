# 应用图标由脚本生成，仓库不存图片二进制

应用包此前没有图标（Dock / Finder / 关于面板都是系统占位图标），补图标时要定的是**它存在哪**。选择把图标画在 `Scripts/make-icon.swift` 里、由 `build-app.sh` 每次构建重画，而不是提交一份 `.icns` 或设计工具导出的图片：这个仓库此前零二进制资产、包由脚本手工组装，图标又是会反复调的品味题——画成代码后，改图标是一次可 diff、可 review 的修改，而不是换一个二进制文件。代价是构建多约 0.6 秒、多一个失败点，且不同 macOS 版本渲染可能有像素级差异（本地构建、不签名的分发方式下可接受）；`build-app.sh` 因此把「图标没生成出来」当成构建失败，而不是交出一个没图标的包。

**Considered Options**：提交生成好的 `.icns` 当构建输入（构建最快、最标准，但仓库多一个 ~1MB 二进制，且脚本与产物会漂移）；只提交手工设计工具产出的 `.icns`（最省事，但设计源不在仓库里，以后改图标要重画）。

**Consequences**：图标不是资产而是代码，评审图标改动的对象是 `Scripts/make-icon.swift` 的 diff。画布按 Big Sur 网格（1024 画布里 824 的主体、圆角 185.4）——macOS 26 起系统会把老格式 `.icns` 归一到这个网格，13–15 不归一但认的也是这个网格，所以一份 `.icns` 同时服务两代系统，暂不做 macOS 26+ 的分层 `.icon`（浅色/深色/着色变体）。
